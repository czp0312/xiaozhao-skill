# 候选人匹配与投递策略

用于岗位匹配、公司排序、投递优先级和短期行动计划。

## 信息收集

先确认：

- 年级与毕业时间；
- 学历、学校、专业；
- 技术栈和熟练度；
- 项目、实习、竞赛、科研、开源经历；
- 目标城市、可实习时长、到岗时间；
- 目标岗位方向和不想投的方向；
- 当前简历版本和准备时间。

信息不足时可以先给暂定判断，但要标注“需要补充的信息”。

## 匹配维度

使用七个维度，0-3 分只作为内部判断辅助：

```text
基础资格匹配
岗位技能匹配
项目相关度
实习/工程经历
竞争力加分项
城市与投递约束
准备成本与时间窗口
```

分数含义：

```text
0 = 明显不匹配或信息缺失严重
1 = 弱匹配，需要大量补强
2 = 基本匹配，可以投递但需要优化表达
3 = 强匹配，应优先投递
```

不要用总分替代解释，必须说明证据。`scripts/score_match.py` 对没有内置技能画像的岗位族会返回 `profile_missing`，此时不要输出总分结论。

## 工科转技术岗方向映射

机械、车辆、自动化、材料、能源、仪器、电子等工科背景的用户，先做方向映射再谈投递排序。判断原则是：**优先选“原专业能构成加分项”的方向，而不是从零开始和计算机科班正面竞争的方向。**

| 原专业优势 | 对口方向 | 需要补的能力 |
| --- | --- | --- |
| 机械设计、结构、CAD/CAE | 机器人本体与结构、运控、嵌硬 | 控制理论、C/C++、电路与 PCB |
| 自动化、控制理论、信号处理 | 运控（运动控制算法）、具身智能（运动规划）、自动驾驶规划控制 | ROS、C++、Linux、仿真工具链 |
| 车辆工程、动力学、底盘 | 智能汽车（线控底盘、整车电子）、自动驾驶规划控制 | 感知基础、SLAM、C++ |
| 机电一体化、单片机课程 | 嵌软（MCU、固件、驱动） | RTOS、CAN/SPI/I2C、C、调试工具 |
| 电子、微电子、光电 | 嵌硬、数字 IC 设计与验证、FPGA | Verilog/SystemVerilog、UVM、时序与综合 |
| 图像处理、光电、仪器仪表 | CV（图像算法、缺陷检测、三维重建） | 深度学习、OpenCV、PyTorch |
| 机器人竞赛、科研项目（视觉 + 控制） | 具身智能、机器人算法 | VLA、强化学习、仿真环境 |
| 工业工程、有数据分析课程 | 数据开发、数据分析 | SQL、Spark/Flink、指标体系 |

方向选择的常见判断：

- 有机器人、控制、嵌入式项目或竞赛的，主投运控、具身智能、嵌软，这类岗位对机械背景的容忍度最高。
- 有 CV 或图像处理项目但缺少深度学习训练的，主投工业视觉、缺陷检测方向，不要直接冲算法研究岗。
- 只有课程和理论、没有工程产出的，先用 2-4 周补一个可演示的工程项目，再谈投递排序。
- 想转纯算法、大模型方向的，需要有论文、竞赛名次或可量化的项目结果，否则按冲刺处理。

## 岗位技能信号

- 前端：HTML / CSS / JavaScript / TypeScript、React / Vue、小程序、工程化、性能优化、组件抽象。
- 后端：Java / Go / C++ / Python、数据库、缓存、消息队列、分布式、服务治理。
- 客户端：Android / iOS / Flutter、网络、端侧性能、稳定性。
- 全栈：前端框架 + 后端语言 + 数据库，能独立交付完整功能。
- AI 应用：Python、LLM API、RAG、Agent、向量数据库、Prompt、前后端集成、评估、成本控制。
- 大模型：预训练、微调（SFT/LoRA）、推理优化、评测、数据构造、分布式训练。
- Agent 开发：工具调用、MCP、工作流编排、多智能体、上下文与记忆管理、效果评估。
- 算法 / 机器学习：数学基础、机器学习 / 深度学习、论文、竞赛、科研或算法项目。
- 计算机视觉：OpenCV、目标检测、图像分割、三维重建、点云、SLAM、PyTorch。
- 具身智能：机器人学习、运动规划、强化学习、抓取、VLA、ROS、仿真环境。
- 运控：运动控制算法、伺服与电机控制、PID、轨迹规划、力控、MATLAB/Simulink、PLC。
- 嵌软：C/C++、MCU、RTOS、固件、驱动、BSP、CAN/SPI/I2C、Linux 驱动。
- 嵌硬：电路设计、PCB、原理图、电源、EMC、信号完整性、硬件调试。
- IC 设计：Verilog/SystemVerilog、UVM、RTL、时序与综合、FPGA、DFT。
- 数据开发：SQL、数仓、Spark / Flink、ETL、指标体系。
- 测试开发：自动化测试、接口测试、质量平台、脚本开发。
- SRE / 运维开发：Linux、网络、容器、Kubernetes、监控、自动化。
- 安全：Web 安全、二进制、安全工具、漏洞挖掘、攻防经验。

## 推荐层级

使用：

```text
主投：基础匹配，准备成本可控，简历能快速对齐。
冲刺：岗位有吸引力但存在明显短板，需要集中补强。
低优先级：硬性条件、技能栈或时间窗口不适合。
```

不要使用“保底”。需要表达相对可行时，用“相对稳妥”。

## 投递排序

排序依据：

1. 硬性条件匹配；
2. 简历与岗位的证据密度；
3. 截止时间紧急程度；
4. 准备成本；
5. 公司、城市、业务偏好；
6. 竞争强度。

简历版本建议控制在 2-3 个：

- 主方向版本；
- 相邻方向版本；
- 特定公司或 JD 定制版本。

## 输出规则

建议用以下结构：

```text

冲刺方向：
低优先级方向：
依据：

补强建议：

```

如果使用 `scripts/score_match.py`，输出时说明它只是轻量辅助评分，最终结论以证据解释为准。
