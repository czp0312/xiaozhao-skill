# JD 分析模块

用于拆解用户提供的岗位描述、判断岗位族、提取准备重点。

## 分析顺序

1. 判断岗位族，先看岗位标题再看正文。
2. 拆分岗位职责和任职要求。
3. 提取硬性要求。
4. 提取加分项。
5. 提取技术关键词。
6. 推断隐含能力，并明确标注为推断。
7. 判断简历应突出什么。
8. 预测面试追问方向。

## 岗位族判断

按“具体方向优先”判断，常见归属：

- 岗位名含“大模型 / LLM / 预训练 / 微调 / 推理优化”→ `llm_app`。
- 岗位名含“Agent / 智能体 / 工具调用 / MCP”→ `agent_development`。
- 岗位名含“具身智能 / 人形机器人 / 机器人学习 / VLA / 抓取”→ `embodied_ai`。
- 岗位名含“运动控制 / 伺服 / 电机控制 / 轨迹规划”→ `motion_control`。
- 岗位名含“嵌入式软件 / 固件 / 驱动 / BSP / MCU”→ `embedded_software`。
- 岗位名含“嵌入式硬件 / 电路 / PCB / 电源 / EMC”→ `embedded_hardware`。
- 岗位名含“数字 IC / 验证 / RTL / Verilog / FPGA”→ `ic_design`。
- 岗位名含“计算机视觉 / 图像算法 / 目标检测 / SLAM / 点云”→ `computer_vision`。
- 岗位名含“游戏客户端 / 引擎 / 渲染”→ `game_development` 或 `graphics`。
- 只写“后端 / 服务端”而正文提到大模型或算法的，仍归 `backend`；正文出现技术词不等于岗位方向。

## 硬性要求识别

常见硬性要求包括：

- 毕业年份、学历、专业；
- 必须掌握的语言、框架、平台；
- 实习时长、到岗时间、工作城市；
- 项目、竞赛、论文、开源或业务经验；
- 岗位特殊限制，如必须线下、必须转正实习；
- 硬件类岗位的器件、工具链或实验室条件要求。

## 加分项识别

常见加分项包括：

- 大厂、AI 公司或强相关业务实习；
- 开源项目、竞赛、论文、专利；
- 真实线上项目、用户规模、性能指标、成本指标；
- 跨端、工程化、复杂业务、基础设施经验；
- RAG、Agent、工具调用、评估体系、LLMOps 等 AI 应用落地经验；
- 机器人、自动驾驶、嵌入式方向的实物作品、比赛名次或整机落地经验。

## 隐含能力推断

以下内容只能作为推断，不能伪装成 JD 明示要求：

- `复杂业务系统`：抽象能力、工程能力、协作能力。
- `高并发/海量数据`：性能、稳定性、分布式系统理解。
- `AI 应用落地`：工程集成、评估、成本控制、异常处理。
- `增长/推荐/广告`：数据意识、实验意识、业务指标理解。
- `基础架构`：系统设计、可靠性、工程基本功。
- `机器人/具身智能`：软硬协同、真实环境调试、仿真与实机差距的处理经验。
- `运控/嵌软`：实时性约束、硬件时序、故障复现与定位能力。
- `芯片/嵌硬`：设计余量、可测试性、跨团队（软件/结构/供应链）沟通。

## 输出模板

```text
岗位定位：
岗位族：
核心职责：
硬性要求：
加分项：
技术关键词：
根据 JD 推断：
简历应突出：
面试可能追问：
准备优先级：
```

回答中要把“JD 明示内容”和“基于经验的推断”分开。
