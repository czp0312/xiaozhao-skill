面向软件开发岗校招、实习和大厂求职的 AI Skill。它把官方招聘入口索引、岗位检索、信息核验、JD 分析、岗位匹配、投递策略、简历诊断、简历改写、面试准备和模拟面试整理成一套可复用的 AI 工作流。

覆盖方向不限于传统开发岗：大模型、Agent 开发、具身智能、计算机视觉、嵌入式软硬件、IC 设计、运动控制等硬科技方向都在范围内，也支持机械、自动化、电子等工科专业转技术岗的方向映射。

## 项目定位

`校招.skill` 不是岗位数据库，也不是求职包过工具。它是一套给 AI 工具使用的校招求职操作手册，目标是让 AI 在处理软件开发岗校招问题时更稳定、更可信、更可执行。

它适合用来：

- 直接找到大厂和热门技术公司的官方招聘入口，而不是在聚合平台里绕路；
- 从官方或近官方来源核验当前可投岗位；
- 拆解岗位 JD，判断真实要求和准备重点；
- 根据候选人背景制定岗位选择和投递优先级，包括工科转技术岗的方向映射；
- 诊断简历问题，并在不编造事实的前提下优化表达；
- 组织技术面、HR 面、项目追问和模拟面试。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 官方入口索引 | 收录 228 家大厂与热门技术公司的官方招聘入口，按 15 个行业分组，标注核验日期。 |
| 当前岗位检索 | 根据公司、岗位、毕业年份、城市和招聘批次整理当前可投机会。 |
| 信息源核验 | 优先使用公司官网、校园招聘站、官方招聘账号和官方招聘系统。 |
| JD 分析 | 拆解职责、硬性要求、加分项、技术关键词和潜在追问。 |
| 岗位匹配 | 根据年级、技能、项目、实习、城市和时间窗口给出投递排序。 |
| 岗位族画像 | 按岗位族汇总真实 JD 归纳出的硬门槛、必备技能、加分项和工科转岗切入点。 |
| 工科转技术岗 | 机械、自动化、车辆、电子等背景的方向映射、能力补强和项目建议。 |
| 简历诊断 | 按问题优先级指出硬伤、强影响问题、中影响问题和细节优化项。 |
| 简历改写 | 保持真实性，突出个人动作、技术方案、难点权衡和结果。 |
| 面试准备 | 生成技术面、HR 面、项目追问链路和模拟面试问题。 |
| 结构化输出 | 用稳定模板输出岗位表、分析结论、改写版本和行动计划。 |

## 官方招聘入口索引

`references/role-profiles.md` 按岗位族整理了真实校招 JD 归纳出的能力画像，覆盖具身智能、运控、CV、大模型、Agent、嵌软、嵌硬、IC 等方向，并给出机械、自动化、电子等专业的转岗切入点。

`references/company-portals.md` 收录 228 家公司的官方招聘入口，覆盖互联网大厂、AI 与大模型公司、计算机视觉与安防、具身智能与机器人、运控与工业自动化、自动驾驶与智能汽车、芯片与算力、通信与 ICT、智能硬件与消费电子、游戏、企业服务与云、网络安全、金融科技等方向。

索引中的每条链接都用真实 HTTP 请求核验过，核验标准不止“状态码 200”：会进一步判断页面能否读到正文、是否命中域名停放页或跳转到占位图。
招聘官网大量使用前端渲染，这类入口标记为 `SHELL`（静态请求读不到岗位正文）；域名停放页标记为 `PARKED`、跳转到图片或文件标记为 `NONHTML`（入口已失效）。

`SHELL` 不等于没救：加 `--render` 会用无头浏览器渲染这些入口，能读到正文的升级为 `OK`。

入口会失效，所以索引本身也带时效：跨过一个招聘季后需要重新核验。批量复核用：

```bash
python scripts/check_portals.py

# 用无头浏览器复核前端渲染入口，能读到正文的升级为 OK
python scripts/check_portals.py --render
```

## 适用场景

适合：

- 校招、春招、秋招、提前批、暑期实习、日常实习、转正实习；
- 互联网大厂、AI 公司、云厂商、智能硬件、新能源、游戏、SaaS、金融科技等公司；
- 前端、后端、客户端、全栈、AI 应用、大模型应用、Agent 开发、算法、计算机视觉、具身智能、运动控制、嵌入式软件、嵌入式硬件、IC 设计、数据、测试开发、SRE、安全、游戏开发等技术岗；
- 机械、自动化、车辆、材料、电子等工科专业转技术岗时的方向选择和背景转译；
- 岗位清单整理、公司招聘入口查询、公司招聘流程查询、JD 拆解、岗位选择、投递排序、简历 review、模拟面试。

不作为默认目标：

- 泛社招、海外岗位、公务员、国企、银行、留学申请、保研、考研规划；
- 如果用户明确要求，可以复用部分方法论，但需要说明适用边界。

## 安装方式

本 Skill 面向 AI 工具中的自然语言安装，不要求用户手动执行技术步骤。

推荐在支持 Skill 安装的 AI 工具中直接输入：

> 帮我从 GitHub 仓库根目录安装这个 Skill：https://github.com/czp0312/xiaozhao-skill

如果 AI 工具要求你确认安装位置，选择仓库根目录即可。这个仓库的根目录已经包含完整 Skill 入口文件。

安装后，重启或刷新 AI 工具，让新 Skill 被重新加载。

## 使用示例

安装后，可以在 AI 工具中直接用自然语言调用：

> 使用 $xiaozhao-skill 帮我找现在可以投的具身智能实习，优先北京、上海、深圳。

> 使用 $xiaozhao-skill 给我大疆、宇树、汇川和地平线的官方招聘入口，我要确认哪些还在招。

> 我是机械专业，做过一个 STM32 的伺服驱动项目，适合投哪些技术岗？

> 使用 $xiaozhao-skill 分析这个 Agent 开发实习 JD，告诉我简历应该突出什么，面试可能追问什么。

> 使用 $xiaozhao-skill 按计算机视觉实习方向 review 我的项目经历，指出 P0 到 P3 问题，并给出不编造事实的改写版本。

> 使用 $xiaozhao-skill 给我做一次嵌入式软件岗技术面模拟面试，一次只问一个问题。

## 工作流模块

| 模块 | 用途 |
| --- | --- |
| Skill 入口 | 定义触发场景、核心原则、适用范围和任务路由。 |
| 官方入口索引 | 维护公司官方招聘入口，按行业分组并记录核验日期。 |
| 信息源系统 | 定义官方来源、近官方来源、线索来源、时效性核验和去重规则。 |
| 候选人策略 | 支持岗位匹配、工科转技术岗映射、投递排序和行动计划。 |
| JD 分析 | 拆解岗位要求，提取硬性条件、加分项和隐含能力。 |
| 简历模块 | 支持简历诊断、项目经历改写和真实性约束。 |
| 面试模块 | 支持技术面、HR 面、项目追问和模拟面试。 |
| 检索排障 | 记录入口抓取、前端渲染、反爬和编码类问题的判定口径与处理协议。 |
| 输出模板 | 保持岗位表、分析结论、复盘建议和行动计划的结构一致。 |
| HTML 报告 | 把调研结论渲染成带图表、卡片和时间线的自包含 HTML 报告。 |

## 脚本与测试

脚本默认只依赖 Python 标准库。读取前端渲染的招聘页（飞书招聘 / 北森 / Moka）需要可选的 Playwright：

```bash
pip install playwright
python -m playwright install chromium
```

没装时相关脚本会降级为静态抓取并给出提示，其余功能不受影响。

```bash
# 岗位记录标准化 + 去重 + 生成 Markdown 表格
python scripts/normalize_jobs.py jobs.json

# 输出标准化 JSON
python scripts/normalize_jobs.py jobs.json --json

# 复核招聘入口索引（SHELL 不算失败，加 --strict 才计入）
python scripts/check_portals.py
python scripts/check_portals.py --json
python scripts/check_portals.py --render

# 抓取岗位 / 招聘页正文；静态读不到时自动用无头浏览器渲染
python scripts/fetch_jd.py https://career.nankai.edu.cn/correcruit/content/id/116497.html
python scripts/fetch_jd.py https://unitree.zhiye.com/campus --render

# 安全合并新核验的入口（先 dry-run）
python scripts/update_portals.py --input entries.json --dry-run

# 把调研数据渲染成 HTML 报告
python scripts/render_report.py report.json --out report.html

# 岗位匹配评分
python scripts/score_match.py match.json

# 提取简历文本
python scripts/extract_resume_text.py resume.docx
```

运行测试：

```bash
pip install -r requirements-dev.txt
python -m pytest tests
```

## 信息源原则

涉及“现在、最新、截止时间、投递链接、是否还在招”等问题时，必须核验时效。

信息源优先级：

1. 仓库内已核验的官方招聘入口索引；
2. 公司招聘官网；
3. 公司校园招聘或实习招聘页；
4. 官方招聘公众号或官方公告；
5. 官方授权招聘系统；
6. 搜索引擎定向查询；
7. 聚合平台和社区线索；
8. 回到官方或近官方来源复核。

正式岗位表只应混入已核验或明确标注状态的信息。聚合平台、截图、个人整理和社区表格只能作为线索，不能直接当成已核验事实。

## 安全边界

本项目坚持以下边界：

- 不编造岗位、截止时间、投递链接、内推码、录用概率或简历事实；
- 不承诺“稳进”“必过”“保底”；
- 不提供笔试、在线测评或实时面试作弊协助；
- 不把个人经验、社区传闻包装成官方规则；
- 不建议用户伪造项目、夸大职责或虚构指标；
- 对不确定信息明确标注“需要核验”“状态不明”或“需要你确认”。

- 是否涉及最新招聘信息或外部来源；
- 是否可能影响信息真实性、安全边界或用户隐私。

请不要提交真实简历、个人隐私、私有内推码、未授权招聘资料或任何可能帮助作弊的内容。

## 常见问题

### 这个 Skill 会自动保存岗位数据库吗？

不会。它提供岗位检索、核验和输出方法，以及官方入口索引。用户每次询问“最新岗位”时，AI 工具都应重新核验当前信息。

### 为什么不能直接相信牛客、实习僧或社区表格？

这些平台适合发现线索，但可能存在过期、转述、链接失效或口径不清的问题。正式输出当前岗位时，应优先回到官方或近官方来源。

### 简历改写会不会帮我包装经历？

不会编造事实。它会优化表达，但缺少指标或结果时，应使用占位表达并让用户确认真实数据。

### 工科专业转技术岗会不会不占优势？

方向选对了就有优势。运控、具身智能、嵌软、嵌硬、智能汽车这类岗位本身就需要软硬协同和真实环境调试能力，机械和自动化背景是加分项，而不是减分项。纯算法和大模型方向竞争更激烈，需要论文、竞赛或可量化的项目结果支撑。

### 可以用于非技术岗吗？

可以临时复用部分方法，但本项目的岗位画像、简历判断和面试准备主要面向软件开发相关技术岗。

### 招聘入口打不开怎么办？

先运行 `python scripts/check_portals.py` 确认是入口失效还是本机网络问题。入口确实失效时，按 `references/source-system.md` 的检索顺序重新查找官方入口，并更新 `references/company-portals.md`。
